Factory Inventory Management: architecture

A demo full-stack app: a Vue 3 single-page app talks to a FastAPI backend over REST. There is no database; the backend loads JSON files into memory at startup and filters them in Python on each request.

System architecture

Two processes on localhost. The browser loads the SPA from Vite (port 3000) and calls the API directly on port 8001; CORS is open to all origins.

Tech stack

Deliberately small: no state library, no chart library, no database.

Data flow: changing a filter

The FilterBar drives every filtered view. Filter state is a module-level singleton, so all components share it.

  1. User picks a filter in FilterBarTime period, warehouse, category or order status. Each is a ref in useFilters.js, declared outside the function so every caller shares the same state.
  2. The view's watch() firesFor example Dashboard.vue watches all four refs and calls getCurrentFilters(), which maps selectedLocation to warehouse and selectedPeriod to month.
  3. api.js sends the requestBuilds URLSearchParams, leaving out any value that is "all". The Dashboard fires four calls in parallel: summary, orders, inventory, backlog.
  4. FastAPI filters in memoryapply_filters() runs list comprehensions over the in-memory lists (case-insensitive for category and status), then filter_by_month() does a substring match on order_date, expanding quarters through QUARTER_MAP.
  5. Pydantic validates the responseEndpoints with a response_model are validated and serialized. Summary, spending and report endpoints return plain dicts without a model.
  6. Vue recomputesThe response goes into raw refs (allOrders, inventoryItems); KPIs and chart data are computed() properties, so the UI updates on its own.
Inventory has no time dimension, so the time-period filter has no effect on /api/inventory. /api/demand, /api/backlog and the spending endpoints ignore all filters.

Gaps found while reading the code

Not visible in the README, but useful to know before building on it.

Tasks API missing. App.vue calls getTasks, createTask, toggleTask and deleteTask, but the backend has no /api/tasks routes (GET returns 404). Tasks also exist as mock data in useAuth.js.
Purchase-order API missing. api.js defines createPurchaseOrder and getPurchaseOrderByBacklogItem, and main.py defines a CreatePurchaseOrderRequest model, but no route uses either.
Backlog view not routed. views/Backlog.vue exists but has no route in main.js; backlog data only shows on the Dashboard.
Hard-coded API base. http://localhost:8001 is hard-coded in api.js.
Quarter filter covers 2025 only. QUARTER_MAP, used by the period filter, lists only 2025 quarters.
